# Native Linux packages

Native packaging targets x86_64 Ubuntu 24.04 / Linux Mint 22.x with DEB and
Fedora 44 with RPM. The build host for the current artifacts is Linux Mint
22.3 (Ubuntu 24.04 base), glibc 2.39, GTK 3.24.41. These packages are not
claimed compatible with every Debian, RHEL, or openSUSE release. The RPM uses
the Flutter bundle built on the Ubuntu-family host; a clean Fedora container
install and headless playback check passed, but a real Fedora desktop and GPU
still need inspection.

Build from the repository root:

```bash
./packaging/scripts/package-linux.sh deb
./packaging/scripts/package-linux.sh rpm
```

Each command builds a release Flutter bundle, checks it, stages all of
`vpfl`, `lib/`, and `data/` beneath `/usr/lib/vpfl`, creates `/usr/bin/vpfl`,
installs a desktop entry, four hicolor PNG icons, and AppStream metadata,
then validates the package. DEB dependencies are calculated from the release
ELF files with `dpkg-shlibdeps`. RPM dependencies are generated by rpmbuild.
The RPM command uses local `rpmbuild` or a disposable `fedora:44` Docker
container, which must be able to install `rpm-build`.

The desktop entry advertises the video containers requested for VPFL: MP4,
Matroska, WebM, QuickTime, AVI, MPEG, MPEG transport stream, FLV, WMV, 3GPP,
3GPP2, Ogg video, and MXF. It uses canonical MIME types from the installed
freedesktop MIME database, including `application/mxf` for MXF. The current
clean-install launch check exercises MP4, Matroska, and WebM; the other
registered formats still need playback checks on target systems. `Exec=vpfl
%f` passes one local file to the existing media open route. Package
installation does not set the system's default video app.
Both packages refresh the freedesktop desktop-entry database on install and
removal, so GLib file managers can list VPFL in Open With. The refresh does
not set a default application.

The release bundle also includes `libdefault_manager_linux_plugin.so`. The
plugin reads or changes per-user MIME defaults through GIO only after the
user confirms the action in VPFL. Removing the DEB or RPM does not delete the
user's MIME preferences. See [default application integration](../linux/default-applications.md)
for the prompt schedule and isolated GIO check.

The media kit Linux plugin links to **system** `libmpv.so.2` and `libepoxy.so.0`.
The DEB therefore depends on `libmpv2` and `libepoxy0`; the Fedora RPM should
require the corresponding SONAMEs, provided by `mpv-libs` and `libepoxy`.
Flutter also loads EGL and GLES dynamically, so ELF scanners do not detect
them. The DEB declares `libegl1` and `libgles2`, and the RPM declares
`libglvnd-egl` and `libglvnd-gles`. A clean Ubuntu install exposed the missing
GLES dependency when VPFL exited with `libGLESv2.so.2` unavailable; this is
why these dependencies are explicit.
Flutter itself and its data are bundled. `libdartjni.so` is present because of
an Android transitive dependency, but VPFL's Linux code does not load it.
It is excluded from runtime dependency scanning so Java is not required for
Linux playback. Recheck this if platform dependencies change.

The repository currently has no project-wide license file. Package metadata
uses `LicenseRef-proprietary` until the project owner chooses and records a
license; this needs resolution before distributing the packages publicly.

Debug ELF files are stored outside the installable packages at
`dist/symbols/<version>-1-x86_64-<commit>/`. `BUILD-INFO` records the full
commit, build OS, glibc, GTK, Flutter version, and architecture. Build in the
oldest supported target environment to avoid accidentally requiring newer
system libraries. User settings, history, and caches remain in the user's XDG
directories and are not managed by these packages.
The runner and locally compiled plugins use `-g` for Release builds; the
packaging script extracts their debug sections before stripping the staged
copies. The prebuilt Flutter engine may not include equivalent debug sections.

## Installation checks

Install the DEB on a disposable Ubuntu 24.04 or Mint 22.x machine with
`sudo apt install ./dist/vpfl_<version>-1_amd64.deb`. On Fedora 44, use
`sudo dnf install ./dist/vpfl-<version>-1.fc44.x86_64.rpm`.
Check `command -v vpfl`, launch `vpfl` and `vpfl /path/to/sample.mp4`,
then check its application menu icon and Open With entry. Uninstall using
`apt remove vpfl` or `dnf remove vpfl` and verify the system files are gone.
Do not remove the user's XDG data. A headless container can check installation
and registered files, but it cannot establish that a desktop window and video
render correctly on the target graphics stack.

For a repeatable container install/launch/removal check, run
`./packaging/scripts/clean-install-check.sh deb dist/vpfl_1.0.0-1_amd64.deb`
or the corresponding `rpm` command with the RPM artifact. The script generates
tiny MP4, Matroska, and WebM samples, installs the package and Xvfb in a fresh
target container, checks the system integration, requires a 320 × 180 video
texture for each sample, then removes the package.

On 4 October 2026, the DEB check passed in a fresh Ubuntu 24.04 container and
the RPM check passed in a fresh Fedora 44 container. Both resolved system
dependencies, registered `com.app.vpfl.desktop` for `video/mp4`, reached a
320 × 180 texture for MP4, Matroska, and WebM, and removed the installed
system files. The Fedora check initially rejected `command -v vpfl` because
its `/usr/sbin/vpfl` path resolves to the installed `/usr/bin/vpfl`; the check
now verifies that the command is available and `/usr/bin/vpfl` is executable.
This was a check-script issue, not a package-install failure. Xvfb does not
verify visible pixels, file-manager presentation, or performance on a real GPU.
